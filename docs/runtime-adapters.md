# Offline Runtime Adapter Contracts

AO Next has provider-neutral normalization contracts for the locally installed Codex and Claude CLIs. Phase-8 qualification used only local `--version` and `--help` commands. It made no model or provider call.

Both adapters prepare structured program-plus-argument invocations, pass the prompt through bounded stdin, preserve one exact worker identity, parse bounded structured output into `AdapterTurn`, and reject malformed output or runtime-identity drift. The shared process runner enforces input, combined-output, timeout, cancellation, working-directory, and missing-executable bounds. It never invokes a shell.

The N7 Codex invocation is ephemeral, ignores user configuration and rules, disables approval escalation and every installed shell, unified-exec, web, browser, computer, image, app, plugin, multi-agent, skill, workspace-dependency, and tool-suggestion surface, uses a read-only sandbox, and requests JSONL plus the checked `adapter-turn-v1` schema. The normalizer accepts only lifecycle envelopes and one agent message; command, file-change, tool, or unknown events fail closed. Before invocation, AO Next deterministically projects tagged-union `oneOf` branches to Codex-compatible `anyOf` branches in a digest-addressed sibling file; the canonical schema stays unchanged and captured output must still decode into the strict canonical `AdapterTurn`. The Claude invocation uses bare print mode, disables persistence and slash commands, supplies an empty strict MCP configuration, and disables all built-in tools.

The v2 provider prompt includes the exact authority digest, native read/write capabilities, empty program list, denied network and external effects, turn/effect/byte limits, relative-path rules, nonexistence binding, and bounded UTF-8 source and visible-fixture inventories. It contains no workspace root, control path, capture path, hidden-test path, or hidden bytes. Hidden tests are explicitly unavailable. `run_program` is absent from the provider schema and denied if it reaches the runtime decoder.

N7 workspace changes occur only through native `read_file` and `write_file` effects. Paths may be workspace-relative and are resolved against the single sealed root. Reads require a matching content digest. Creates require the `sha256` digest of `ao.next.file-does-not-exist.v1`; replacements require the current UTF-8 preimage digest. Writes are bounded, symlink-free, regular-file-only, synced to a same-directory create-only temporary file, rechecked, and atomically published. Unix retains descriptor-relative traversal and exchange verification. Windows retains non-reparse root, ancestor, parent, and file handles, blocks parent replacement while an effect is admitted, revalidates file identity immediately before replacement, and uses an atomic same-volume rename. The terminal record retains each native effect's identifier, status, stdout, stderr, and output digest. Trusted verifier programs run afterward through the separately digest-bound verifier runner and are never model authority; live and preflight commands also require operator-supplied corpus and verifier-profile digest anchors outside the input JSON.

The N4 baseline is a separate fixed Codex invocation. It is ephemeral, ignores ambient configuration and rules, disables approval escalation, and uses the native workspace-write sandbox. Its prompt carries the same source, workspace, objective, policy, and verifier bindings as N7. The model never selects the verifier or live authority.

Runtime usage comes only from Codex `turn.completed` or Claude result envelopes. Codex non-fatal `item.completed/error` diagnostics are accepted only with their exact bounded shape; tool and unknown events still fail closed. Trusted Codex usage accepts the legacy `reasoning_tokens` or Codex 0.147 `reasoning_output_tokens` field, never both. The harness overwrites model-authored counters, stores each bounded status/stdout/stderr digest, and binds the ordered capture-digest list into the measurement. Trusted total usage is the checked sum of input, cached input, reasoning, and output tokens. Cached input cannot exceed input, and reasoning cannot exceed output. Missing, duplicate, malformed, contradictory, overflowed, or over-limit trusted usage fails after capture verification and before post-capture controls. A one-turn prompt explicitly requires all necessary effects followed by `verify` in the same actions array.

The provider commands require `AO_NEXT_LIVE_PROVIDER_CALLS=operator-authorized`. The gate is checked before the input path or executable is resolved. Live contract smoke tests remain ignored behind their separate `AO_NEXT_LIVE_ADAPTER_TESTS=operator-authorized` gate. Model output is data and cannot alter either process environment. Sanitized help fixtures and fake captures contain no credentials, account identifiers, sessions, or real provider output.
