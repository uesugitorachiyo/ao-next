# AO Mission v0.1.1 Release Notes

AO Mission `v0.1.1` advances durable mission supervision and evidence
reconciliation across the AO Stack while preserving Mission's no-execution
authority boundary.

## Included Capabilities

- Import and reconcile canonical AO Atlas terminal indexes with strict source,
  state, schema, digest, and lineage checks.
- Preserve durable checkpoints through restart, compaction, replay, and
  continuation without reviving completed historical work.
- Plan bounded qualification soaks from measured history with fixed retry,
  timeout, repeat, and lease policies before activation.
- Supervise credential-free issue-repair and package canaries through
  digest-bound readbacks rather than direct repository mutation.
- Reject stale, contradictory, malformed, oversized, or over-authority
  downstream evidence before it can change mission state.
- Build release candidates with an explicitly pinned Go 1.26.4 toolchain and
  strict native executable smoke checks.

## Supported Release Artifacts

The release publishes native archives for:

- Linux x86_64
- macOS aarch64
- Windows x86_64

Each archive contains the AO Mission binary, license and notice files, exact
version evidence, credential-free functional smoke evidence, an SBOM,
provenance, and the approved release manifest.

## Verification

The release workflow binds these notes, the candidate archives, and the
immutable promotion plan to the exact source commit. It verifies native binary
identity, archive inventory, checksums, provenance, and installed behavior
before its protected publication job can run.

After extracting an archive, verify the installed candidate with:

```sh
ao-mission --version
ao-mission doctor --json
```

## Safety Boundaries

AO Mission records objectives, lifecycle state, routing decisions,
checkpoints, and evidence. It does not execute downstream repository mutations,
approve work, merge pull requests, publish releases, deploy software, or grant
provider authority. Fixture and gateway paths remain credential-free and
readback-only during qualification. RSI remains denied.
