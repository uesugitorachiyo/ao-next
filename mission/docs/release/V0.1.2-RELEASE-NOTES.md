# AO Mission v0.1.2 Release Notes

AO Mission `v0.1.2` clarifies terminal projection semantics while preserving
the durable source record and Mission's no-execution authority boundary.

## Included Capabilities

- Projects a validated canonical Atlas terminal index as read-only completion
  without mutating the active Mission source record.
- Exposes source status, terminal projection status, projection read-only
  state, and effective operator status consistently across Mission and Command
  views.
- Preserves one shared terminal index digest while retaining distinct
  surface-specific state digests for inspect, checkpoint, event-index, and
  Command-compatible readbacks.
- Rejects contradictory node counts, timing, lineage, digest, and authority
  claims before final reconciliation.

## Supported Release Artifacts

The release publishes native archives for:

- Linux x86_64
- macOS aarch64
- Windows x86_64

Each archive contains the AO Mission binary, license and notice files, exact
version evidence, credential-free functional smoke evidence, an SBOM,
provenance, and the approved release manifest.

## Verification

The release workflow binds these notes, the candidate archives, and the
immutable promotion plan to the exact source commit. It verifies native binary
identity, archive inventory, checksums, provenance, and installed behavior
before its protected publication job can run.

After extracting an archive, verify the installed candidate with:

```sh
ao-mission --version
ao-mission doctor --json
```

## Safety Boundaries

AO Mission records objectives, lifecycle state, routing decisions,
checkpoints, and evidence. It does not execute downstream repository mutations,
approve work, merge pull requests, publish releases, deploy software, or grant
provider authority. Fixture and gateway paths remain credential-free and
readback-only during qualification. RSI remains denied.
