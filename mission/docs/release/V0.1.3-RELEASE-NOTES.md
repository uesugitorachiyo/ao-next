# AO Mission v0.1.3 Release Notes

AO Mission `v0.1.3` adds a reusable Python repair product gate while preserving
the durable lifecycle ledger and Mission's no-execution authority boundary.

## Included Capabilities

- Validates a sealed Python repair pack against exact repository, issue,
  source, candidate, fixture, and evidence digests.
- Replays credential-free positive and negative repair fixtures without
  contacting a model provider or third-party repository.
- Rejects stale, malformed, mismatched, unsafe, or over-authority repair
  evidence before importing its result into Mission.
- Produces deterministic product-gate readbacks for cross-platform
  qualification and canonical terminal reconciliation.

## Supported Release Artifacts

The release publishes native archives for:

- Linux x86_64
- macOS aarch64
- Windows x86_64

Each archive contains the AO Mission binary, license and notice files, exact
version evidence, credential-free functional smoke evidence, an SBOM,
provenance, and the approved release manifest.

## Verification

The release workflow binds these notes, the candidate archives, and the
immutable promotion plan to the exact source commit. It verifies native binary
identity, archive inventory, checksums, provenance, and installed behavior
before its protected publication job can run.

After extracting an archive, verify the installed candidate with:

```sh
ao-mission --version
ao-mission doctor --json
```

## Safety Boundaries

AO Mission records objectives, lifecycle state, routing decisions,
checkpoints, and evidence. It does not execute downstream repository mutations,
approve work, merge pull requests, publish releases, deploy software, or grant
provider authority. The Python repair product gate validates bounded evidence;
it does not contact providers or mutate third-party repositories. RSI remains denied.
