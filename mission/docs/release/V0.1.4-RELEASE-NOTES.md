# AO Mission v0.1.4 Release Notes

AO Mission `v0.1.4` strengthens terminal lifecycle correctness, immutable
release finalization, and correlation-bound compaction readbacks while
preserving Mission's no-execution authority boundary.

## Included Fixes

- Reconciles a completed imported Atlas workgraph without retaining a stale
  executable next action.
- Imports and validates the exact sealed release-rehearsal candidates during
  immutable release finalization instead of rebuilding promotion inputs.
- Preserves `correlation_id` in ledger and timeline compaction readbacks so a
  correlated Mission can import producer output unchanged.
- Documents the source-owned compaction contract and its legacy uncorrelated
  compatibility behavior.

## Supported Release Artifacts

The release candidate contains native archives for:

- Linux x86_64
- macOS aarch64
- Windows x86_64

Each archive contains the AO Mission binary, license and notice files, exact
version evidence, credential-free functional smoke evidence, an SBOM,
provenance, and the approved release manifest.

## Verification

The release workflow binds these notes, all candidate archives, and the
immutable promotion plan to one exact source commit. Finalization rejects a
wrong run, source, version, tag, manifest digest, archive digest, workflow
identity, or rebuilt candidate before publication can begin.

After extracting an archive, verify the installed candidate with:

```sh
ao-mission --version
ao-mission doctor --json
```

## Safety Boundaries

AO Mission records objectives, lifecycle state, routing decisions,
checkpoints, and evidence. It does not execute downstream repository mutations,
approve work, merge pull requests, publish releases, deploy software, or grant
provider authority. Release qualification and a positive release decision do
not authorize publication. RSI remains denied.
